# Expected outputs (determinism proof)

These files are the committed proof that Spektr is deterministic: the same input
produces the same bytes. They are regenerated by a script, not edited by hand.

## What is here

- `sample_run.trimmed.json`: the `spektr` metadata (with a pinned timestamp and the
  input hash) plus every `modules` slot, from a fixed run on `assets/samples/`. The
  non-deterministic `engine` block is dropped (see below).
- `sample_dashboard.html`: the Output Forge HTML dashboard from the same run, byte
  for byte.

## Why trimmed, not the full run.json

The vendored engine writes a temporary output path and its own wall-clock timestamp
into `engine.run_metadata`, so the full `run.json` is not byte-stable across runs.
Everything Spektr computes on top is: every module slot, and the HTML dashboard. The
proof therefore stores the deterministic parts and omits the engine block.

## Regenerate and check

From the plugin root:

```bash
# Rewrite the files from a fresh deterministic run
python scripts/regenerate_expected_outputs.py

# Compare a fresh run against the committed files (used by the test suite and CI)
python scripts/regenerate_expected_outputs.py --check
```

The fixed inputs that define the proof (sample corpus, module list, client domain,
brand, pinned timestamp) live in `scripts/regenerate_expected_outputs.py`. Change one
and the expected bytes change; rerun without `--check` to update the committed files.
